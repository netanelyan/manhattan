The problem

The layout doesn’t fit on the GPU. It never will.

A modern block holds tens of millions of cell placements, and a chip places that block dozens of times. A GPU can draw about two million rectangles at 60 fps. That was measured on an RTX 4060 at 3440×1440, and every design decision here follows from it.

Desktop tools handle this by loading the design into memory. The status bar of the signoff tool our target users keep open was seen reading Mem: 9.0GB, and those users report slow load times.

Manhattan streams tiles against a 64 MB cache instead. The design is never handed to the renderer whole. It only needs to draw what is on screen, at the detail the screen can actually show.

How it works

One invariant: everything is an axis-aligned rectangle.

Digital layout is Manhattan geometry. That lets the whole pipeline be built around rectangles, from the tile format to the shaders.

far

Density blocks

The whole die at once. Placements merge into density blocks, drawn with the macros and the power grid. At the chip view that is one tile fetched and 70 draws.

mid

One outline per cell

Each placement is one rectangle in one draw call. Mid geometry stops being drawn at 1.5 px per cell, before it turns into noise.

deep

Full cell internals

Poly, contacts, metal and pins. Draws are grouped by rect-count bucket instead of by master, so a library of 4,634 masters costs 8 draw calls rather than about 4,400.

Parses nothing at runtime

Tiles are binary, laid out so the viewer takes typed-array views straight over the bytes. The data goes from fetch to GPU buffer with no parse step.

LOD solved per design

Switch points come from each design’s tile costs and your canvas size, not from constants. A 1.3× hysteresis band stops the level flickering when you stop on a boundary.

Block instancing

A block is tiled once, and the chip is a list of transforms over it. 70 instances of a 5M-placement block take 117 MB, where flattening them would take about 8.2 GB.

Lazy deep tiles

Deep levels are 96% of the pyramid, and a session opens only a few hundred of their tiles. They are built on request from a placement index in 0.22 ms at p50.

Click to identify

The tile itself is the spatial index, so there is no second structure to keep in sync. Click a cell to see what it is, or press g to jump to a coordinate.

A layer panel you’ll recognise

Grouped rows with separate visible and selectable columns, based on the panel in the signoff tool users already know. Process layers and instance categories share one list.

Shareable views

The URL is the view.

A desktop layout viewer can’t do this: paste a link into a design review and have the other person land on the same rectangle, with the same layers and the same selection. The URL updates as you move around, but it doesn’t fill your back button with every pan.

localhost:8080/src/?data=data-sb16&view=812400,640250,0.018&mask=0x1f4&pick=812533,640190

Real designs, not only a generator

Tested on real designs, including the parts that broke

A format built to fit its own generator will always look fine on that generator. So Manhattan also reads real LEF/DEF files. Two public designs have been through it so far, and the problems they exposed are written down next to the results.

What real data changed: a 17-layer process stack against 12 layer ids (34% of the library’s rects ended up on metal3), a power grid that isn’t made of cell placements at all, and cells whose geometry extends past their SIZE box. These are listed as known gaps, not left out.

Two gates

An empty frame fails the build.

make verify reads every binary back and checks each invariant of the format. make check then runs the real viewer in headless Chrome and visits every point where geometry provably exists, at every level. If the screen is empty where geometry exists, the check fails.

Tiles built on request must be byte-identical to written ones. That check once caught a 200 nm offset that passed every other test, because 200 nm is smaller than a pixel.

Where it’s going

Roadmap

  1. done
    End-to-end pipeline

    Generator, three-representation pyramid, lazy tiles, WebGL2 viewer, layer panel, shareable URLs, and both gates.

  2. done
    Real LEF/DEF import

    superblue16 and routed sky130 gcd, from the CLI or by dropping files into the browser.

  3. next
    A wider layer id space

    Room for a real 17-layer stack, so a macro shows its pins on metal5 instead of rendering as one solid slab.

  4. next
    Routing as wires, not placements

    A fourth wire tile kind and a net table, so power grids and signal routes are stored as what they are.

  5. later
    Names and search

    Instance names as a side table (7.23 MB on superblue16), so you can search for a cell and jump to it.
